# 08 Data pipeline and storage

## Stages
```
data/
  raw/        1. Exactly what we downloaded. Never edited. Git-ignored. Recorded in MANIFEST.json
  interim/    2. Parsed and cleaned, one table per source (Parquet)
  processed/  3. Merged catalogue: works, authors, series, editions, sources (Parquet)
  labels/     4. LLM outputs (premises and tags), append-only (JSONL)
```
Every stage is rebuilt by scripts from the stage before it. Only `raw/` and `labels/` are expensive to recreate.

## Storage formats (D-012)

| Stage | Format | Why |
|---|---|---|
| **raw: downloaded datasets** | **Original files, byte for byte** (e.g. `book.json.gz`) | Keeps us faithful to the source and reproducible. Never convert raw data |
| **raw: scraped web pages** | **gzip-compressed HTML**, one file per page, plus a JSONL fetch log | Lets us re-parse later without re-crawling (politeness, and site changes) |
| **interim / processed** | **Parquet** | Typed columns, list fields (`genres[]`), compressed, fast; readable with pandas and DuckDB; UTF-8 always |
| **labels (LLM output)** | **JSONL**, append-only | One record per line: easy to resume after a crash, easy to diff, and keeps the model and prompt version per record |
| **Exports / inspection** | CSV **only** for quick viewing, written as UTF-8 with BOM (`utf-8-sig`) so Excel shows Bangla | Not a storage format |

### Why not CSV for storage
- Bangla summaries contain commas, quotes and line breaks, so CSV quoting breaks easily.
- There are no types: numbers, nulls and lists become strings, and list fields need workarounds.
- Excel on Windows opens UTF-8 CSV as garbled Bangla unless it has a BOM.

### Why not plain JSON for large tables
- A single large JSON array must be loaded fully into memory, and a partial write corrupts the whole file.
- JSONL (one object per line) fixes both, so we use it for streaming LLM output. Parquet is better for tables.

## raw/MANIFEST.json
Each raw file gets an entry:
```json
{"path": "rokomaribg/book.json.gz", "sha256": "…", "bytes": 39944189,
 "source_url": "https://github.com/backlashblitz/Bangla-Book-Recommendation-Dataset",
 "license": "CC BY-NC 4.0 (HF mirror tag)", "fetched_at": "2026-09-26"}
```
- The checksum proves the raw file hasn't changed since download.
- Generated by `scripts/make_manifest.py`. Re-run it after adding raw files; it keeps existing entries.

## Rules
1. **Raw is read-only.** Cleaning code reads from `raw/` and writes to `interim/`.
2. **Keep the source ID** (e.g. Rokomari `book_id`) on every derived row, so any row can be traced back.
3. **UTF-8 everywhere**, and Unicode normalisation happens in the interim stage, not in raw.
4. **Idempotent scripts.** Running a script twice gives the same output.
5. **Snapshots, not edits.** A re-crawl creates a new dated raw folder (`raw/boitoi/2026-10-01/`); old snapshots are kept.

## Findings from profiling RokomariBG (see [reports/rokomaribg-profile.md](reports/rokomaribg-profile.md))
- 149,515 rows → **127,302 unique books**. Repeated IDs are identical re-scrapes, so keep the longest summary.
- **"Show More" suffix** on 99.7% of summaries (scraper artifact), so strip it.
- After stripping, **58% of books have no summary**. 36.6k have 500+ characters.
- Summaries contain noise: flap-text prefixes (4.1%), tables of contents (2.0%), prefaces (3.7%) and English text (4.0%).
- Title noise: binding suffixes such as `(Paperback)` and `(Hardcover)`, honorifics such as `(সা.)`, and series tags in brackets.
- **14.4% share title + author with another book**, likely editions, to merge into works.
- Categories include merchandising lists ("Boimela 2025", "July Triumph!!"). Keep only genre-like categories.
- **Origin:** ISBN prefix (984 = Bangladesh, 81/93 = India) is present on about 57% of books. Publisher names carry "(India)", which is a stronger signal.
- Review text exists for only 17.7k books (Rokomari shows reviews on 29.7k).
- **About 13k fiction books have a summary of at least 200 characters**. This is the realistic size of the first catalogue.

## Cleaning steps (planned, in order)
Sources for each technique are listed in [09 Literature review](09-literature-review.md).
1. Deduplicate rows by `book_id`, keeping the longest summary (D-013)
2. Strip "Show More"; normalise whitespace; Unicode-normalise Bangla (`bnunicodenormalizer` + NFC, clean ZWJ/ZWNJ)
3. Normalise fields: Bangla digits → ASCII, validate ISBN-10/13 checksums, explicit nulls
4. Detect the script and language of each field (Bangla / Latin / mixed)
5. Clean titles: split off binding and format suffixes (`(Paperback)`); keep series and volume tags (`(২য় খণ্ড)`) in separate fields
6. Classify summaries: flap text / excerpt / table of contents / preface / English / empty; keep only usable ones for premises
7. Map categories to our `genres` and `format` (hand-made mapping table); drop merchandising categories
8. Set `origin` from publisher "(India)" first, then ISBN prefix, then a translation category
9. Group editions into works with a normalised author+title key (OCLC FRBR-style); later, fuzzy matching with an LLM for ambiguous cases
10. Build the author table: merge duplicate names (pre-filter, then an LLM decides); link to Wikidata QIDs; add romanised aliases (IndicXlit)
11. Attach review text (for mood signals). Star ratings are weak: 65.8% are five-star.

### Later labelling stage (for reference)
- Premises from blurbs, not reviews, with a spoiler check.
- Tags: one facet per prompt, from the fixed vocabulary, then drop tags that aren't supported by the source text.
